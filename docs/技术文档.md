# Pulse 脉搏 · 技术文档

> 版本：v1.0 ｜ 面向开发者与运维
> 本文档描述技术栈、代码结构、接口约定、认证授权、构建与部署。产品设计见《设计文档》。

---

## 1. 技术栈

### 后端
- **语言/框架**：Java 17 + Spring Boot 3 + Spring Security 6
- **持久层**：MyBatis-Plus 3 + MySQL 8
- **安全**：JWT（HS256，access + refresh）、Spring Security 过滤器链
- **实时**：Spring WebSocket + STOMP + SockJS
- **文档**：SpringDoc OpenAPI（默认关闭）
- **构建**：Maven（含测试）

### 前端
- **框架**：Next.js 16（App Router，**静态导出** `output: export`）
- **UI**：React 19 + TypeScript + Tailwind CSS v4 + Radix UI
- **状态/数据**：TanStack Query（服务端状态）+ Zustand（客户端状态）+ Zod（校验）
- **实时**：`@stomp/stompjs` + `sockjs-client`
- **交互**：`@dnd-kit`（看板拖拽）、`sonner`（提示）、`lucide-react`（图标）
- **构建**：Node 20，`npm ci && npm run build` → `frontend/out`

### 部署
- 单一 Fat JAR（前端静态资源内嵌于 `src/main/resources/static`）
- Docker 多阶段构建；`docker-compose` 编排 `db` + `app` + `proxy(nginx)`
- nginx 终止 TLS，反向代理至 `app:8080`，`/ws/` 升级 WebSocket

## 2. 代码结构（后端）

```
src/main/java/com/pulse/
├── common/        Result/PageResult、BusinessException、GlobalExceptionHandler
│                  TenantContext、Role、EncryptionUtil、PasswordUtils
├── config/        SecurityConfig、WebMvcConfig、MyBatisPlusConfig
│                  MybatisMetaObjectHandler、OpenApiConfig、AdminInitRunner
├── controller/    23 个 REST 控制器（见 §4）
├── dto/           请求/响应对象（LoginRequest、TokenPair、MemberVO …）
├── entity/        21 个表实体（@TableName）
├── interceptor/   TenantInterceptor（多租户/成员校验）、RateLimitInterceptor
├── mapper/        21 个 MyBatis-Plus Mapper
├── realtime/      WebSocketConfig、RealtimeChannelInterceptor、RealtimeController
├── scheduler/     BurndownScheduler、ReminderScheduler
├── security/      JwtAuthFilter、JwtUtils
├── service/       21 个业务服务
└── PulseApplication   启动类（@MapperScan + @EnableScheduling）
```

### 2.1 分层约定
- **Controller**：仅做参数绑定与权限前置（`@PreAuthorize` 用于管理后台类级），不含业务逻辑。
- **Service**：业务逻辑与事务（`@Transactional`），统一抛 `BusinessException`。
- **Mapper**：MyBatis-Plus 接口，复杂 SQL 走 XML/注解。

### 2.2 统一响应
```json
{ "code": 0, "message": "ok", "data": { } }
```
- `Result.ok(data)` / `Result.fail(message)`；`code != 0` 表示业务失败。
- 分页：`PageResult`（含 `total`/`list`）。

### 2.3 异常处理
- `GlobalExceptionHandler`（`@RestControllerAdvice`）统一捕获：
  - `BusinessException` → 对应 `code/message`
  - `AccessDeniedException` → 403
  - 参数校验失败 → 400
  - 兜底 → 500（不泄露堆栈）

## 3. 认证与授权

### 3.1 JWT
- `JwtUtils`：HS256，签发 access（默认 24h）与 refresh（默认 7d）。
- `JwtAuthFilter`（OncePerRequestFilter）：
  1. 提取 `Authorization: Bearer`；
  2. 校验通过后查 `users`，设置 `TenantContext`（userId、systemAdmin）；
  3. **禁用账户直接拒绝**（返 401）；
  4. 构建 `SecurityContext`：`ROLE_USER` 必含，`ROLE_ADMIN` 仅系统管理员。
- refresh token 写入 `HttpOnly + Secure + SameSite` Cookie，路径 `/refresh`。

### 3.2 多租户上下文
- `TenantInterceptor`（`WebMvcConfig` 注册）：读取 `X-Team-ID`：
  - 普通成员：校验该团队属于自己 → 写入 `TenantContext.tenantId`；
  - 系统管理员 + `X-Team-ID: all` → 开启 `godView`（跨团队查询）。
- `TenantContext`：ThreadLocal 持有 `tenantId / userId / systemAdmin / globalView`，请求结束 `clear()`。

### 3.3 角色判定（AuthorizationService）
```java
isSystemAdmin()           // users.is_system_admin
isGodView()               // 系统管理员 + 全局视图
isTeamLead(teamId)        // team_members.role = LEAD
requireTeamLead(teamId)   // 否则抛 "需要管理员权限"
isLastTeamLead(...)       // 最后一名队长保护
```
- 管理后台 `AdminController` 类级 `@PreAuthorize("hasRole('ADMIN')")`；Service 层 `verifyGlobalAdmin()` 二次校验。

### 3.4 实时鉴权（WebSocket）
- `RealtimeChannelInterceptor`：CONNECT 阶段解析 JWT 设 Principal；SUBSCRIBE 阶段校验
  - `/topic/notifications.{userId}`：仅本人可订阅；
  - `/topic/board.{pid}`：仅项目所属团队成员可订阅。
- 消息处理（`RealtimeController`）中 `TenantContext` 未注入，故从 `Principal` 取 userId 并二次校验团队归属（SEC-04）。

## 4. API 约定

- **前缀**：`/api/v1`。
- **认证豁免**：`/api/v1/auth/**`、静态资源、`/uploads/**`、`/swagger-ui/**`（仅 `SWAGGER_ENABLED=true`）。
- **团队上下文**：业务接口须带 `X-Team-ID`（管理后台全局视图用 `all`）。
- **分页**：`?page=&size=`（部分接口）；返回 `PageResult`。
- **主要控制器**：

| 控制器 | 路径前缀 | 职责 |

| ProjectController | `/api/v1/teams/{teamId}/projects` | 项目 CRUD/状态/归档 |
| AppProjectController | `/api/v1/projects` | 顶层项目路由（X-Team-ID 解析） |
| TaskController | `/api/v1` | 任务 CRUD/移动/批量/看板/我的任务/标签 |
| TaskDependencyController | `/api/v1/tasks/{id}/dependencies` | 任务依赖 |
| CommentController | `/api/v1/tasks/{id}/comments` | 评论 |
| AttachmentController | `/api/v1/tasks/{id}/attachments` | 附件 |
| CustomFieldController | `/api/v1` | 自定义字段/取值 |
| ColumnController | `/api/v1/projects/{pid}/columns` | 看板列 |
| SavedViewController | `/api/v1/projects/{pid}/saved-views` | 保存视图 |
| TagController | `/api/v1/teams/{tid}/tags` | 标签 |
| IterationController / AppIterationController | `/api/v1` | 迭代 |

## 5. 数据库

- **初始化**：`schema.sql`（幂等：`CREATE TABLE IF NOT EXISTS` + 增量 `ALTER` 迁移）+ `data.sql`。
  - `sql.init.mode: always`；每次启动重跑，`schema.sql` 不丢数据。
- **编码**：`utf8mb4`；时区 `Asia/Shanghai`。
- **核心表**（详见《设计文档》§2）：`users`、`teams`、`team_members`、`projects`、`tasks`、`task_dependencies`、`iterations`、`tags`/`task_tags`、`board_columns`、`custom_fields`/`custom_field_values`、`saved_views`、`task_comments`、`task_attachments`、`task_activity_logs`、`notifications`、`audit_logs`、`burn_down_snapshots`、`user_llm_configs`、`task_sequences`。
- **审计**：`audit_logs` 记录成员管理、团队设置、项目增删、管理员跨团队操作等敏感动作（操作者姓名反范式化存储）。
- **迁移示例**（角色重构）：`UPDATE team_members SET role='USER' WHERE role='MEMBER';`（幂等）。

## 6. 加密与密钥

- **用户 LLM Key**：`EncryptionUtil` 用 AES-256-GCM，主密钥 `PULSE_ENCRYPTION_KEY`（64 位十六进制 / 32 字节）。
  - 缺失或非法 → 启动失败（fail-fast）。
  - 生成：`./scripts/gen-key.sh`。
- **JWT 密钥**：`JWT_SECRET`（HS256），缺失 → 启动失败；生成：`openssl rand -hex 32`。
- **数据库**：`MYSQL_ROOT_PASSWORD` 必填；应用以 root 复用该口令。

## 7. 构建

### 7.1 一体化构建（推荐）
```bash
./scripts/build.sh            # 前端 npm ci+build -> static；后端 mvn package
# 产物：target/pulse-1.0.0.jar（内含前端静态资源）
SKIP_FRONTEND=1 ./scripts/build.sh   # 仅打包后端
```
- 前端 `frontend/out` 经 `scripts/build.sh` 同步至 `src/main/resources/static`。
- `Dockerfile`：多阶段（node 构建前端 → maven 打包），最终 `java -jar target/pulse-1.0.0.jar`。

### 7.2 本地开发
```bash
# 后端
./mvnw spring-boot:run
# 前端（独立 dev server，默认 http://localhost:5173）
cd frontend && npm ci && npm run dev
```
> 生产形态为单 JAR + 内嵌静态资源；开发期前端可独立运行，经 `CORS_ALLOWED_ORIGINS` 对接后端。

### 7.3 构建期与运行期职责分离（为何无需 Node 运行时）
Pulse 采用 **Next.js 静态导出（`output: export`）+ Spring Boot 内嵌静态资源** 的架构，将「前端运行」彻底剥离出运行环境：

- **构建期（需要 Node.js）**：仅在源码变更、需要重新打包时执行。
  1. `npm ci && npm run build` → 在 `frontend/out` 生成纯静态文件（HTML/CSS/JS，`/_next/static/chunks/*` 等，无服务端渲染进程、无长驻 Node 服务）。
  2. `scripts/build.sh` 将 `frontend/out` 同步进 `src/main/resources/static/`。
  3. `mvn package` 把 `static/` 编译进 `target/pulse-1.0.0.jar` 的 `BOOT-INF/classes/static/`。
- **运行期（仅需 JVM）**：Jar 启动后，Spring Boot 通过 `ResourceHttpRequestHandler` 直接托管这些静态文件：
  - `GET /` → `index.html`；
  - `GET /_next/*`、`/assets/*` → 对应静态文件；
  - SPA 深链由 `SpaController` 转发回 `index.html`；
  - 前后端同源同端口，API 走 `/api/v1`，无需跨域、无需独立前端服务。
- **结论**：生产部署 = 一个 `java -jar pulse-1.0.0.jar` 进程。无 Node 进程、无独立前端 server、无反向代理到 dev server。Node.js 仅在「重新构建前端」环节出现。

## 8. 部署（Docker Compose）

### 8.1 准备
```bash
cp .env.example .env
./scripts/gen-key.sh                 # 生成 PULSE_ENCRYPTION_KEY，写入 .env
# 生成 JWT_SECRET 并写入 .env：
openssl rand -hex 32
```
`.env` 至少需：`MYSQL_ROOT_PASSWORD`、`PULSE_ENCRYPTION_KEY`、`JWT_SECRET`；缺失即 fail-fast。

### 8.2 启动
```bash
docker compose up -d --build
```
- `app` 暴露 8080（仅内部）；`proxy` 对外 `443`（TLS）+ `80`（跳转 HTTPS）。
- 容器内仅有 Java 进程；前端静态资源已内嵌于 Jar，无需前端容器或 Node 运行时（详见 §7.3）。
- 卷：`pulse-db`（MySQL 数据）、`pulse-uploads`（上传文件，重建不丢）、`pulse-certs`（证书）。
- 证书：`./certs`（fullchain.pem + privkey.pem）；缺失时 nginx 生成自签名（仅内网/测试）。

### 8.3 配置项（环境变量）
| 变量 | 说明 | 默认值/必填 |
|---|---|---|
| `MYSQL_ROOT_PASSWORD` | 数据库 root 口令 | 必填 |
| `DATASOURCE_URL` | JDBC URL | 内置（db:3306/pulse） |
| `JWT_SECRET` | JWT 签名密钥 | 必填 |
| `JWT_EXPIRATION` | access 有效期(ms) | 86400000 |
| `JWT_REFRESH_EXPIRATION` | refresh 有效期(ms) | 604800000 |
| `PULSE_ENCRYPTION_KEY` | LLM Key 加密主密钥 | 必填 |
| `CORS_ALLOWED_ORIGINS` | 前端域名(逗号) | localhost:8080 |
| `AI_BASE_URL` / `AI_MODEL` | 默认 LLM 服务 | openai 兼容 |
| `APP_UPLOAD_DIR` | 上传目录 | /app/uploads |
| `SWAGGER_ENABLED` | 开启 API 文档 | false |
| `SQL_INIT_MODE` | schema 初始化模式 | always |

### 8.4 健康检查
- `GET /actuator/health`（仅暴露 health）；容器探活依赖它。
- 首次启动日志含初始管理员账号 `admin@pulse.dev` 与一次性随机口令，**须立即登录改密**。

## 11. 常见问题

- **Q：改了前端但没生效？** 确认 `scripts/build.sh` 已把 `frontend/out` 同步进 `src/main/resources/static` 并重新打包；不要用旧 `static` 覆盖。
- **Q：WebSocket 连不上？** 确认经 `wss://` 且 nginx 已对 `/ws/` 做 Upgrade 转发；前端连接带 `Authorization: Bearer`。
- **Q：上传文件容器重建后丢失？** 确认 `pulse-uploads` 卷已挂载（docker-compose 默认挂载）。
- **Q：API 文档打不开？** 设置 `SWAGGER_ENABLED=true` 并重启。
